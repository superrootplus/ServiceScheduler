Продолжи разработку ServiceScheduler в существующем репозитории, не начинай проект с нуля.

Сначала полностью прочитай AGENTS.md, README.md и KIMI_CODE_HANDOFF.md. Затем выполни git status --short и git log -1 --oneline. Сохрани все незакоммиченные изменения, появившиеся после передачи.

Актуальное приложение — WPF в wpf/, сборка штатным C# compiler .NET Framework 4.x. Python-файлы относятся к прежнему варианту.

Ключевые решения, которые нельзя случайно откатить:
- своё задание открывается во встроенном TaskDialog, системное — во встроенном окне только для чтения; заголовок содержит точное имя задания;
- свойства службы открываются через MMC20.Application в STA с проверкой точного имени в заголовке;
- результат открывает LogWindow с фильтром по TaskInfo.Path;
- виртуальный список заданий MMC и старый IScheduledWorkItem для вложенных заданий проверены и не работают; не восстанавливай NativeListView/MSAA без новых оснований;
- чужие системные задания нельзя изменять, а kill общего процесса требует явного разрешения.

После изменения пересобери приложение, прогони функциональные и UI-тесты, проверь исходный сценарий end-to-end, удали временные задания, выполни git diff --check и просмотри git status. Обнови справку и документацию под новое поведение.

Не коммить dist, диагностику, локальные артефакты, логины, пароли, токены, ключи или другие секреты. Commit, push и релиз делай только по явному запросу пользователя после успешных проверок.
