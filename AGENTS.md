# Инструкции для бота-разработчика

Действуют для всего репозитория. Пользователь общается преимущественно на русском языке.

## Старт

1. Прочитайте `README.md`, `KIMI_CODE_HANDOFF.md` и актуальный запрос пользователя.
2. Выполните `git status --short` и `git log -1 --oneline`. Не сбрасывайте и не перезаписывайте чужие незакоммиченные изменения.
3. Текущее приложение — WPF в `wpf/`. Не начинайте проект с нуля на основе старых Python-файлов.
4. Сохраняйте существующий стиль: C# для .NET Framework 4.x, без новых библиотек и современных возможностей C#, которые не поддерживает штатный `csc.exe`.

## Сборка и тесты

Из корня репозитория:

```bash
cmd.exe //c build_wpf.cmd
cmd.exe //c build_smoke.cmd
cmd.exe //c build_ui_smoke.cmd
./dist/ServiceScheduler.UiSmokeTests.exe
```

`dist/ServiceScheduler.SmokeTests.exe` запускайте повышенным от администратора. Функциональные тесты изменяют временные задания в `\ServiceManager`; после прогона проверьте их удаление. UI-тесты запускаются обычным пользователем.

Перед завершением изменения:

- пересоберите основной EXE;
- прогоните функциональные и UI-тесты;
- проверьте исходный пользовательский сценарий end-to-end, а не только компиляцию;
- выполните `git diff --check` и просмотрите итоговый diff;
- проверьте `git status`, не добавляйте созданные тестами артефакты;
- обновите справку и документацию, если поведение изменилось.

## Критические архитектурные решения

### Свойства заданий

Щелчок по имени задания обрабатывается в `MainWindow.OpenTaskScheduler`:

- своё задание открывается в `TaskDialog` и может редактироваться;
- системное задание открывается во встроенном окне только для чтения;
- заголовок окна обязан содержать точное `TaskInfo.Name`.

Не заменяйте это открытием общего `taskschd.msc`. Проверка показала, что `MMC20.Application.View.ListItems` возвращает ноль для заданий в `ServiceManager`, а старый `IScheduledWorkItem.EditWorkItem` не поддерживает вложенные задания. Native/MSAA/ListView и клавиатурные попытки также не подтвердили открытие точного окна. Не восстанавливайте эти механизмы без нового подтверждённого основания.

### Свойства служб

`WindowsEditors.OpenService` использует `MMC20.Application` в STA-потоке:

1. Загружает `services.msc`.
2. Находит точное отображаемое имя в `View.ListItems`.
3. Вызывает `View.Select` и `View.DisplaySelectionPropertySheet`.
4. Проверяет новый диалог по имени службы в заголовке.

`Application.UserControl = 1` оставляет оснастку пользователю. Не закрывайте и не освобождайте COM-приложение преждевременно. Недостаточно проверить только появление `services.msc`.

### Журнал

Ссылка «Результат» вызывает `ShowLog(task)`. `LogWindow` должен сохранять фильтр по `TaskInfo.Path`. Не превращайте этот переход в общий нефильтрованный журнал.

### Задания и исполнитель

- Свои задания хранятся в `\ServiceManager`; чужие системные задания доступны только для просмотра.
- Не разрешайте удаление или запуск чужих заданий.
- При сохранении используется защищённый исполнитель `%ProgramData%\ServiceScheduler\ServiceScheduler.exe`.
- Изменения аргументов `--exec` синхронизируйте с `Scheduler.BuildExecutorArguments`, `Program.RunExecutor` и миграцией исполнителя.
- Принудительное завершение общего процесса требует явного разрешения. Не ослабляйте эту защиту.

## Тестирование и код

- Для новых исправлений сначала добавьте воспроизводящий тест в существующие `SmokeTests.cs` или `UiSmokeTests.cs`, убедитесь в его ошибке, затем исправляйте код.
- Не создавайте отдельный тестовый фреймворк и не добавляйте зависимости без необходимости.
- Не оставляйте диагностические методы в производственном коде. Временные probes размещайте только в игнорируемом `dist`.
- После изменения удалите комментарии и справку, описывающие прежнее поведение.

## Git и релизы

- `dist`, `backups`, `__pycache__` и результаты диагностики не коммитьте.
- `README.md`, этот файл и материалы передачи, наоборот, должны оставаться в репозитории для следующего бота.
- Commit и push выполняйте по явному запросу пользователя после успешных проверок.
- Публичный репозиторий: `https://github.com/superrootplus/ServiceScheduler`, основная ветка `main`.
- Релиз 2.1.0: тег `v2.1.0`, исходный коммит `ff84623`.
- При выпуске новой версии обновите `Program.Version`, `AssemblyVersion`, `AssemblyFileVersion`, справку и README. Не переиспользуйте опубликованный тег.

Подробная история проверок и текущее состояние — в `KIMI_CODE_HANDOFF.md`.
